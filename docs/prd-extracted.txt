1. Product Overview

1.1 Nama Produk

Personal AI Knowledge Assistant

Nama sementara dapat diganti nantinya.

1.2 Deskripsi

Personal AI Knowledge Assistant adalah aplikasi berbasis AI yang memungkinkan
pengguna menyimpan berbagai informasi pribadi seperti:

     catatan
     dokumentasi
     artikel
     materi belajar
     PDF
     TXT
     Markdown
     informasi pekerjaan
     dokumentasi project
     knowledge base pribadi

Pengguna kemudian dapat berinteraksi dengan seluruh data tersebut melalui interface chat
menggunakan pendekatan Retrieval-Augmented Generation (RAG).

Contoh:

        User: "Bagaimana cara deployment project Laundry Hub yang pernah aku
        catat?"

AI akan:

    1. memahami pertanyaan,
    2. melakukan semantic search terhadap knowledge milik user,
    3. mengambil dokumen yang relevan,
    4. memasukkan context tersebut ke prompt LLM,
    5. menghasilkan jawaban,
    6. menampilkan sumber informasi yang digunakan.

2. Problem Statement

Informasi pribadi pengguna biasanya tersebar di berbagai tempat:
     Notion
     Google Docs
     file PDF
     catatan lokal
     dokumentasi project
     Markdown
     chat
     knowledge base pribadi

Masalahnya adalah pengguna kesulitan menemukan kembali informasi tersebut.
Traditional search memiliki keterbatasan.
Misalnya user memiliki catatan:

        "Untuk deploy React ke VPS, gunakan Nginx sebagai reverse proxy..."
Kemudian user bertanya:

        "Gimana cara publish frontend React ke server?"
Keyword search mungkin tidak menemukan dokumen tersebut karena kata "publish
frontend React" berbeda dengan "deploy React ke VPS".
Dengan semantic search + embeddings, sistem dapat memahami bahwa kedua konsep
tersebut berkaitan.

3. Product Goals

Primary Goals

    1. User dapat menyimpan knowledge pribadi.
    2. User dapat meng-upload dokumen.
    3. Sistem otomatis memproses dokumen menjadi embeddings.
    4. User dapat bertanya melalui chat.
    5. AI dapat menjawab berdasarkan knowledge milik user.
    6. AI tidak boleh menggunakan knowledge milik user lain.
    7. AI dapat menampilkan sumber jawaban.
    8. Chat dapat menerima respons secara streaming.

     multi-document reasoning

Contoh konsep policy:

document_chunks
conversations
messages
Jangan hanya mengandalkan filter:

di application layer.
Security harus tetap enforced di database.

43. Acceptance Criteria
Authentication

Given user belum login
When membuka halaman private
Then user diarahkan ke login.

Knowledge

Given user login
When membuat knowledge
Then knowledge hanya dapat dilihat oleh user tersebut.

Document

Given user upload PDF
When processing selesai
Then document memiliki status READY dan chunks tersedia.

Embedding

Given document telah diproses
When embedding selesai
Then setiap chunk memiliki vector embedding.

RAG

Given user memiliki document relevan
When user bertanya mengenai isi document
Then sistem mengambil relevant chunks dan menggunakan chunks tersebut sebagai
context LLM.

Security
Given User A dan User B memiliki documents masing-masing
When User A melakukan query
Then retrieval tidak boleh mengembalikan chunk milik User B.

Chat

Given user mengirim pertanyaan
When LLM menghasilkan jawaban
Then jawaban ditampilkan secara streaming.

Sources

Given jawaban menggunakan document tertentu
When response selesai
Then UI menampilkan source document yang digunakan.
